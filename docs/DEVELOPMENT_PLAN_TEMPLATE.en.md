# Development Plan Template

## Purpose

This document defines the required section order for `DEVELOPMENT_PLAN.en.md`.

## Required Section Order

### 1. Document Control

- `plan_id`
- `job_id`
- `prepared_at`
- `prepared_by`

### 2. Problem Statement

- problem summary
- current user or operator pain

### 3. Goals

- primary goals
- measurable success signals when available

### 4. Non-Goals

- explicit exclusions
- deferred work that must not silently enter the freeze

### 5. Assumptions

- repo assumptions
- runtime assumptions
- approval or credential assumptions

### 6. Current Repo Baseline

- base branch
- observed `base_commit`
- important repo constraints

### 7. Intended Execution Surface

- planned adapters
- expected run roles
- any local GUI automation expectation

### 8. Architecture Direction

- design direction
- key boundaries or invariants

### 9. Milestones

- milestone list
- sequencing notes

### 10. Story Breakdown

- story IDs
- objective for each story
- acceptance IDs for each story
- dependency notes when relevant

### 11. Testing Strategy

- required checks
- required environments
- evidence expectations

### 12. Delivery Checklist

- required artifacts
- required reports
- archive or handoff expectations

### 13. Risks

- known risks
- mitigations or fallback plan

### 14. Open Questions

- unresolved scope questions
- decisions that block freeze generation

### 15. Approval Touchpoints

- owner approval gates
- expected change request gates

### 16. Approval Requested

- exact approval being requested
- next action if approved
- next action if rejected

## Stability Rule

The required headings above are normative. Additional appendices may follow them, but they must not replace them.
